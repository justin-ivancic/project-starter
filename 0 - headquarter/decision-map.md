# Project Decision Map

This map keeps durable project decisions visible without turning every planning note, research result, or historical idea into a source of truth.

Status key:

- `current`: implement from this unless a newer accepted decision supersedes it.
- `blocked`: the affected path needs an explicit decision or external fact before it can safely continue.
- `deferred`: intentionally outside the current scope.
- `watch`: a plausible direction or known concern that should not be overbuilt yet.

Founder authority applies across this map. Technical, legal, research, and operational evidence may identify obligations, defects, and risk, but it does not silently make founder-owned product, design, naming, business, rollout, deployment, public-promise, or risk-acceptance decisions.

## How To Maintain This Map

- Record accepted, durable decisions—not proposals or meeting notes.
- Keep each decision specific enough to implement and verify.
- Link to the answer, specification, code contract, or other source that established it.
- Update or supersede stale entries when direction changes; do not leave two active truths.
- Put unanswered founder questions in `founder-inbox.md`, then integrate the answer here once accepted.
- Put implementation work on the taskboard; this map is not a backlog.
