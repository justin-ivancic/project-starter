# Permanent Founder-Inbox Intake Rules

This section is a durable workflow contract, not an inbox item. Do not remove, archive, or rewrite it while clearing answered questions.

Before adding a founder question, inspect the Decision Map, canonical documentation, current behavior, and existing tasks. Research or advice that disagrees with an established direction does not make that direction open again.

Resolve technical and local implementation questions from code, documentation, tests, or reliable technical research. Escalate only decisions that genuinely belong to the founder, such as product direction, design intent, naming, legal or policy choices, business model, rollout, deployment, cost, public promises, or risk acceptance.

Every founder question must:

- use plain language;
- ask for one concrete decision;
- explain why the decision belongs to the founder;
- identify the exact path that is blocked;
- state what safe work can continue without the answer;
- avoid storing secrets, credentials, private user data, or sensitive operational details.

A founder question blocks only the path it affects. Isolate that path and continue useful work elsewhere.

After the founder answers, integrate the answer into the Decision Map, canonical documentation, implementation, and taskboard as appropriate. Then remove the resolved question from this file so it does not keep resurfacing.
